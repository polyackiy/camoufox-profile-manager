# Перенос профиля между компьютерами

[English](sync-guide.md)

Экспериментальная синхронизация включена в установщики **v0.6.0-rc.5**, но
выключена до явной настройки пользователем и подключения отдельных профилей. Она рассчитана
на одного владельца и его доверенные устройства. Нужен собственный relay-сервер;
аккаунт поставщика не требуется. Скачайте установщик для своей платформы со
[страницы rc.5](https://github.com/polyackiy/camoufox-profile-manager/releases/tag/v0.6.0-rc.5).
Зависимости синхронизации уже включены; Python и Node для менеджера не нужны.
Relay разворачивается отдельно. Перед использованием проверьте
[матрицу тестирования](sync-support-matrix.md).
Внешний аудит безопасности остаётся условием стабильного выпуска.

## Подготовка

На обоих компьютерах должны совпадать протестированные ОС, архитектура процессора
и сборка Camoufox. Назначенные через библиотеку расширения пока блокируют
синхронизацию: снимите назначения или оставьте профиль локальным. Сам браузер не
изменяется. Остальные профили работают как раньше.

Для установки из репозитория:

```sh
uv sync --extra sync --extra dev
uv run --no-sync python scripts/build_webui.py
uv run --no-sync camoufox-pm user add owner
uv run --no-sync camoufox-pm
```

Войдите под администратором на каждом компьютере. API-ключ и анонимный локальный
доступ не дают права подключать устройства. Настройте сервер по
[инструкции оператора](sync-relay.md); понадобятся его HTTPS-адрес и токен регистрации.

## Первый компьютер

1. Откройте **Settings → Device synchronization**. Укажите адрес сервера и имя
   компьютера.
2. Выберите системное хранилище ключей. Если оно недоступно, явно выберите
   зашифрованный файл и придумайте пароль разблокировки.
3. Сохраните зашифрованный recovery-файл. Секрет восстановления сохраните отдельно:
   в загруженный файл он намеренно не включён.
4. Выберите сохранённый файл и введите отдельно сохранённый секрет. Менеджер
   проверит восстановление ключей в отдельном процессе.
5. В **Connect your relay** введите токен регистрации сервера.

Первый компьютер хранит ключ владельца; остальные получают собственные ключи
устройств. Потерю всех ключей и recovery-файла с секретом нельзя исправить сбросом
пароля сервера.

## Второй компьютер

1. Перенесите код владельца из Settings на второй компьютер.
2. Подготовьте подключение и верните полученный код запроса владельцу.
3. Сравните **полный отпечаток** через отдельный доверенный канал. Владелец
   подтверждает совпавший запрос и возвращает код разрешения.
4. Подтвердите тот же отпечаток на новом компьютере и примите разрешение.

При прерывании используйте возобновление сохранённого подключения или изменения
состава устройств. Не создавайте ключи заново. Отзыв устройства блокирует будущий
доступ, но не стирает уже скачанные данные и не закрывает браузер без связи.

## Передача профиля

1. Закройте браузер. В меню действий профиля откройте **Device synchronization**,
   подтвердите передачу сессий доверенным устройствам и включите синхронизацию.
2. Нажмите **Send to another device** и дождитесь **Ready for another device**.
   Закрытие синхронизированного браузера также ставит передачу в очередь. При
   системном хранилище она выполняется в фоне, пока менеджер открыт; файловое
   хранилище ждёт пароль. Очередь сохраняется после перезапуска.
3. На другом компьютере откройте **Profiles from trusted devices**, добавьте
   профиль и нажмите **Get latest profile**. Запускайте его после состояния
   **Ready on this device**.
4. Для возврата снова закройте профиль и передайте его. Потеря сети сама по себе
   не освобождает профиль для другого устройства.

После подключения нового устройства отправьте профиль заново: новый снимок
должен включать его ключ. Несовместимая сборка браузера и отсутствие ключа
проверяются до захвата профиля. Для профилей, созданных позже подключения,
владелец передаёт обновлённый код списка профилей нужному устройству.

Передаются cookies, локальное хранилище, отпечаток, настройки и прокси — внутри
шифрования. Учётные записи менеджера, права, расписания и локальные пути остаются
на своём компьютере.

При сбое возобновите ту же операцию. При конфликте сохраните обе стороны;
**Preserve as a new local copy** создаёт отдельную локальную копию, не меняя
исходные права синхронизации. Другой экземпляр той же браузерной личности может
ещё работать. После отката менеджера потребуется новая проверка синхронизации.

Для восстановления на чистом компьютере храните также зашифрованный комплект
снимка: [экспорт и восстановление](sync-recovery-guide.md). Историческая резервная
копия не доказывает актуальность удалённого состояния.

## Если устройство потеряно

Восстановление доступно только на компьютере владельца, где сохранены ключи
владельца. Обычный подключённый компьютер не получает эти права.

1. В **Settings → Device synchronization → Trusted devices** найдите потерянное
   устройство и нажмите **Revoke device**. Дождитесь публикации отзыва; при сбое
   используйте **Resume membership update**.
2. В меню нужного профиля откройте **Device synchronization**. Для профиля,
   который удерживает другое устройство, выберите **Recover from lost device**.
   При файловом хранилище сначала введите пароль разблокировки.
3. Прочитайте предупреждение и нажмите **Recover revoked device profile**.
   Менеджер проверит подписи, возможность расшифровки и совместимость снимка до
   перехвата профиля, затем применит его с журналом восстановления.
4. Дождитесь **Ready on this device**. Перед запуском проверьте активные сессии
   на сайтах и при необходимости отзовите доступ потерянного устройства там.

Используется последний опубликованный снимок. Неотправленные изменения с
потерянного устройства недоступны. Локальная неотправленная копия на компьютере
владельца сохраняется в резервной копии. Отзыв и перехват не могут закрыть
браузер, работающий без сети, или отозвать уже существующие сессии сайтов.
При конфликте истории, несовместимом браузере или отсутствии ключей операция
останется заблокированной: сохраните данные и используйте отдельную локальную
копию либо процедуру исторического восстановления.

Перед публикацией отзыва менеджер пытается проверить последние переданные
версии профилей, пока устройство ещё авторизовано. Проверка ограничена по времени.
Если часть версий проверить не удалось, отзыв всё равно выполняется, а интерфейс
показывает предупреждение о восстановлении. Версия со старым составом устройств,
впервые полученная уже после отзыва, не становится доверенной автоматически:
нужна ранее сохранённая независимая контрольная точка либо отдельная историческая
копия для восстановления.

## Передача после обрыва

**Resume pending transfer** продолжает передачу сохранённого зашифрованного файла
с подтверждённой сервером позиции. Не удаляйте приватный каталог передачи менеджера.
Изменённые данные браузера никогда не шифруются повторно в тот же поток.
Незавершённая загрузка истекает через семь дней. После подтверждённого истечения
явный повтор создаёт новую версию с новым шифрованием, если история и право работы
с профилем по-прежнему согласованы; исходный локальный шифротекст сохраняется.

## Синхронизируемая корзина

На устройстве, которое удерживает профиль, закройте браузер и выберите **Device
synchronization → Move synchronized profile to Trash**. Подтверждение публикует
подписанную зашифрованную версию с отметкой удаления. Данные и история сохраняются;
другие компьютеры увидят удаление при следующем получении версии.

Получивший отметку компьютер блокирует запуск. **Apply deletion on this device**
после подтверждения переносит локальный профиль в восстанавливаемую корзину,
сохраняя его данные и права доступа. Для восстановления откройте **Trash → Device
synchronization → Restore synchronized profile**. Менеджер проверит снимок,
сохранит локальные неотправленные данные в резервной копии и опубликует новую
активную версию. Передайте её другому устройству обычным действием отправки.
На компьютере, где копия ещё в корзине, нажмите **Check for restoration**:
менеджер проверит и установит восстановленную версию. Если актуальная версия
по-прежнему удалена, локальные данные останутся в корзине. После сбоя нажмите
**Resume pending transfer**. Обычное локальное восстановление или окончательное
удаление не обходит ограничения синхронизации. Остановить офлайн-браузер удалённо
невозможно.

## Очистка старых версий владельцем

По умолчанию история сохраняется. На компьютере с ключами владельца откройте
**Device synchronization → Historical storage cleanup → Load verified historical
versions**. Выберите ненужные старые версии (до 64 за один раз), заранее сохраните
нужные [офлайн-пакеты восстановления](sync-recovery-guide.md), затем подтвердите
**Sign cleanup decision**. Текущая версия, подписанная история и локальные резервные
копии остаются на месте.

Сервер ждёт не менее семи дней после получения решения и не начинает раньше
подписанной владельцем даты. Показанная дата — нижняя граница, а не расписание
оператора. Пока очистка не началась, доступна **Cancel historical cleanup**.
Неподтверждённую отмену нужно повторить. Оператор запускает ограниченную процедуру
из [инструкции relay](sync-relay.md). После удаления старого шифротекста восстановить
эту версию можно только из отдельно сохранённого пакета. Копии, ранее загруженные
другими устройствами, такая очистка не удаляет.
