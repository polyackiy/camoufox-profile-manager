# Interface localization

English source messages, Russian (`ru`) and Simplified Chinese (`zh-CN`) share
the existing `useI18n` provider. Russian and the revised first-run checklist are
unreleased changes for the combined 0.7.0 work block, not a separate release.

## Translation contract

- Put every visible source message in both catalogs under `web/src/lib/locales/`.
  Keep named placeholders identical in every translated variant. Use complete
  messages rather than concatenated sentence fragments.
- Russian count entries use `one`, `few`, `many`, and `other`. `Intl.PluralRules`
  handles zero, teens, larger counts and fractions. A missing count uses `other`.
- Localize known diagnostics when rendering. Unrecognized upstream diagnostics
  stay in their original language as plain text; do not invent an explanation,
  interpolate untrusted HTML, or claim every provider error is translated.
- Interface language belongs to the manager only. Do not copy it into profile
  languages, locale, timezone or fingerprint, and do not write profiles when it
  changes. Keep drafts intact when another tab changes the selected language.
- Follow the first supported language in the browser's preference order until
  the user makes an explicit choice. Persist that choice when storage is
  available; blocked storage must still allow switching for the current visit.

## Verification

From `web/`, run `npm test`, `npm run lint`, `npx tsc --noEmit`, and
`NEXT_EXPORT=1 npm run build:static`. From the repository root, run
`.venv/bin/python web/tests/localization_ui.py` (Chromium/Playwright required).
CI installs the same test dependencies through `uv`.

The locale-specific suite uses isolated browser contexts and fictional profiles,
accounts and proxy endpoints. It covers both languages for installation retry,
profile creation/run/stop, drafts across language changes, blocked storage,
compact proxy dialogs and keyboard focus, template counts, launch/stop batches,
access grants, update preparation and explicit experimental-sync consent.
Existing workflow suites continue to test the underlying operations separately.

To retain screenshots, set `CPM_LOCALIZATION_SCREENSHOTS` to an output folder.
Review first-run and compact-dialog images in both languages. Do not use real
profile names, provider credentials, recovery secrets or active sessions.

These are static-export browser acceptance checks. They do not replace native
installer acceptance or testing platform-specific webview behavior before release.
